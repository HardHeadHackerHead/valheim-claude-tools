# Templates

Code to copy into a mod (change the namespace). Each one is the version our own mods run, after the bugs in the skills were fixed.

| File | What it does |
|---|---|
| `ServerSettings.cs` | Settings the server decides in multiplayer: `Synced.Bind(...)` for gameplay settings, and a player on a server with the mod plays by the server's values (their config file keeps their own, even when saved meanwhile). Edits to the .cfg apply while the game runs; the host and the server's admins change the server's values from Configuration Manager (checked on the server against its admin list), everyone else sees them read-only. `Synced.Server` says whether the server has the mod and which version, and `NeedsServer(piece or recipe)` keeps pieces and items out of the menus on a server without it (it would delete them). Never kicks anyone. No library; does what ServerSync does that matters (https://github.com/blaxxun-boop/ServerSync), and hot-reloads. |
| `Costs.cs` | What a piece or recipe costs and where it's made, as settings a server owner can change: "FineWood:12, BronzeNails:30", "forge:2". A setting with any mistake keeps the last good cost (never free by a typo). Pair it with `ServerSettings.Bind`. |
| `Content.cs` | A mod's items, recipes, smelter/oven/fermenter conversions, creature drops and trader goods put into the game by name, safely on every register (`ZNetScene.Awake`, `ObjectDB.Awake`, `CopyOtherDB`, a reload): sets `m_dropPrefab` (an item without it is saved with no name and lost), registers the items' status effects, one `Recipe_<prefab>[_<way>]` per way to make it with its cost from a `Costs.cs` setting, removes its own earlier entries from the game's prefab lists before adding (the libraries add again at every load), sells at a trader through a `Trader.GetAvailableItems` postfix, and on unload takes out only what still points at this copy. Needs `Costs.cs`; works with `ItemReload.cs` (`ItemExtras`). |
| `GameUi.cs` | Windows in the game's own look (on/off switches, number steppers, sliders, the game's text box, live bars and more; see its header), cloned from the inventory screen: wood panel, sunken boxes, buttons, the braided title line, the crafting screen's tabs, the inventory's own item cells (icons, durability, quality, tooltips, clicks), compact item chips with tooltips, progress bars, icons, a scrolling list with the game's scrollbar and scroll speed, a place on the HUD, the game's fonts and colours, a canvas that follows the player's interface scale, and the input patches every window needs (no walking or zooming underneath it, a free cursor, Escape closes only it). Its comment shows a whole window. The Recycler's and the Bounty Board's windows are built with it. |
| `PieceReload.cs` | Lets a mod with build pieces be reloaded while you play (`reload YourMod`) without losing pieces or leaving placed ones on the old code: the piece stays registered across the reload, and pieces standing in the world get the new copy's components. Pieces only: for items, add `ItemReload.cs`. |
| `ItemReload.cs` | The same for a mod's items: they stay registered and alive across the reload, the new copy replaces them by name in ZNetScene and ObjectDB, and the items in the player's bag, loaded chests and on the ground get the new copy's prefab. modcheck gives `world` only to a mod that adds items to ObjectDB through this class alone and calls its `Repoint`. |
| `Leftovers.cs` | Frees what an older copy made, after a hot reload. .NET keeps the old copy's code (a few MB), but its prefabs, materials, meshes, icons and sounds stay too, and `PieceReload`/`ItemReload` keep the old prefabs alive on purpose: every reload left a full set (35 MB a reload for a mod with 30 icons; 2 GB after a night of reloads). `Leftovers.Own(x)` what you make, `HandOver()` in `OnDestroy`, `TakeOver()` once the new copy's own exist: it puts them in the old ones' place where they're still used (standing pieces, item icons in bags and chests, sounds, UI) and destroys the rest, keeping an old item prefab a loaded item still points at. |
| `Translations.cs` | Words in the player's language through the game's own translations: `translations/English.json` and one file per language built into the DLL, `T("key", args)` in code and `"$key"` in the game's own fields, switching with the game's Language setting, players' own corrections in `BepInEx/config/translations/<GUID>/`. No library, no patches; hot-reloads. The **valheim-mod-start** skill ("Words in the player's language") has the rules. |
| `Skill.cs` | A skill of your own in the skills window: `new Skill("your.mod.guid", "Tailoring", "$yourmod_skill", "$yourmod_skill_description", icon)`, then `p.RaiseSkill(skill.Type)`, `skill.Factor(p)`, `skill.Gain` (live, from a synced setting). Its number is a hash of the id: never change the id (moving off SkillManager: `type: Skill.SkillManagerType("English name")`). The game drops a modded skill the first time the character loads without the mod; this keeps a backup in the character's custom data and puts the level back. Its name shows where the game uses `$skill_<number>`, and `raiseskill`/`resetskill` find it (with tab completion). Own Harmony id, hot-reloads in a world. |
| `ContainerAccess.cs` | Taking from or putting into chests the player didn't open, safely in multiplayer: only built chests (not graves, carts or creatures), not one someone has open, ward and lock respected, taken over and reloaded before touching it. |
| `Icon.cs` | Pictures for the build menu and the inventory drawn from your own model when the game starts, so a piece copied from a chest doesn't show the chest: `piece.m_icon = Icon.Make(prefab)` (its `Model` child, or every renderer it shows), `Icon.MakeItem(itemPrefab, setIcon: true)` (from above, from its `attach` child, into `m_shared.m_icons`). A camera and light that see only a layer of their own, the copy made with networking and terrain changes switched off and removed in `finally`, particles left out of the framing, and an embedded PNG when the picture comes out empty. |
| `StatusEffects.cs` | Your own buffs and debuffs made in code: `Create<T>("YourMod_SE_x", "$key", icon)`, `Register()` from ObjectDB's Awake and CopyOtherDB (a world load swaps its list), `Apply`/`Has`/`Remaining`/`Remove` on any character (someone else's goes to its owner). `Unload()` takes them off every character before destroying them, and after a hot reload they go back on with the time they had left. Its comment lists the pitfalls (shared lists in clones, not saved, no icon no HUD). |
| `Registry.cs` | Not searching the scene, and big jobs a slice per frame. `Live<T>`: every live one of a component, kept by the objects themselves (`Add` in `Awake`, `Remove` in `OnDestroy`, or a postfix on the game's `Awake`), with `All`, `Near` and a one-time `Seed` after a hot reload. `Sliced`: a job written as a coroutine run at most a millisecond or two per frame, resting a few seconds between passes (the world's iterative ZDO search one call a frame). Its comment has the real costs that made it (a scene search every 2 s: 20-25 ms) and the two rules for sliced work (read once per pass; check again what you kept). |
| `SnapPoints.cs` | Snap points that fit your piece: a copy of a game prefab keeps the prefab's (a pole's top and bottom float your copy 1 m up or sink it 1 m; chests and stations have none, so a copy never lines up). `SnapPoints.Clear(prefab)` takes them off, `SnapPoints.Box(prefab, min, max)` puts one on each corner of its base (optionally its top and edge middles), `SnapPoints.Add(prefab, "bottom", Vector3.zero)` anywhere; made as the game makes its own (switched-off direct children tagged `snappoint`, named so the snap-point picker shows "Corner 1"). |

**`project/`** is a whole mod project to start from: copy the folder to where you keep your mods (not inside the game's folder),
rename `mods/ExampleMod`, and build. It has the game references (`mods/Directory.Build.props`), shared code compiled into each mod
(`mods/Shared`: the AI disclosure Thunderstore asks for, and `Translations.cs` for any mod with a `translations/English.json`), an
example mod with its words in three languages, and `publish.ps1` for sharing through the mod manager (F7). Its `README.md` walks
through it. The same folder is `template/` in https://github.com/HardHeadHackerHead/valheim-mod-manager.
